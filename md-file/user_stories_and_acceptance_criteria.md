# User Stories and Acceptance Criteria (E-Book Store Mini Project)

เอกสารระบุความต้องการฟังก์ชันระบบร้านขาย E-Book จำแนกตามบทบาทผู้ใช้งาน (Customer & Admin) พร้อม Acceptance Criteria ตามเกณฑ์ใบงานวิชา Database Mini Project

---

## 1. Storefront Module (ระบบหน้าร้านสำหรับลูกค้า)

### US-01: การลงทะเบียนและการเข้าสู่ระบบ (Authentication & Profile)
* **User Story:** ในฐานะผู้เยี่ยมชมเว็บไซต์ ฉันต้องการสมัครสมาชิกและเข้าสู่ระบบด้วยอีเมล/รหัสผ่าน เพื่อเข้าถึงการสั่งซื้อและดูประวัติคำสั่งซื้อส่วนตัว
* **Acceptance Criteria:**
  1. ระบบต้องไม่อนุญาตให้อีเมลซ้ำกันในระบบ (`UNIQUE constraint`)
  2. รหัสผ่านต้องได้รับการแฮช (เช่น bcrypt) ก่อนจัดเก็บลงฐานข้อมูล
  3. เมื่อเข้าสู่ระบบสำเร็จ ระบบต้องระบุตัวตนและบทบาท (Customer/Admin) อย่างถูกต้อง
  4. ผู้ใช้สามารถแก้ไขข้อมูลพื้นฐานของตนเองได้ (ชื่อ, นามสกุล, เบอร์โทรศัพท์)

### US-02: การค้นหาและคัดกรองหนังสือ (E-Book Browsing & Filtering)
* **User Story:** ในฐานะลูกค้า ฉันต้องการค้นหาหนังสือด้วยชื่อเรื่อง หรือคัดกรองตามหมวดหมู่ เพื่อเลือกดูหนังสือที่สนใจได้รวดเร็ว
* **Acceptance Criteria:**
  1. ระบบแสดงรายการ E-Book พร้อมข้อมูล: ชื่อเรื่อง, ผู้แต่ง, ราคา, หมวดหมู่, ภาพปก, คำอธิบายย่อ และสถานะความพร้อมขาย
  2. มีช่อง Search ค้นหาจากชื่อหนังสือหรือคำสำคัญ (Keyword) ได้อย่างถูกต้อง
  3. มี Filter คัดกรองตามหมวดหมู่ (Category) อย่างน้อย 1 หมวดหมู่ขึ้นไป
  4. หนังสือที่มีสถานะ "ปิดการขาย" (`is_active = FALSE`) ต้องไม่แสดงในผลการค้นหาของหน้าร้าน

### US-03: การจัดการตะกร้าสินค้า (Shopping Cart)
* **User Story:** ในฐานะลูกค้า ฉันต้องการเพิ่มหนังสือลงตะกร้า ปรับเปลี่ยนรายการ และตรวจสอบยอดรวมก่อนตัดสินใจสั่งซื้อ
* **Acceptance Criteria:**
  1. ลูกค้าสามารถกดเพิ่ม E-Book ลงตะกร้าสินค้าได้
  2. เนื่องจากเป็น E-Book สินค้าชนิดเดียวกันไม่ควรมีจำนวนซ้ำซ้อนเกิน 1 เล่มต่อคำสั่งซื้อ หรือระบบต้องแจ้งเตือนหากมีอยู่แล้วในตะกร้า
  3. ลูกค้าสามารถลบรายการ E-Book ออกจากตะกร้าสินค้าได้
  4. ระบบคำนวณยอดเงินรวม (Grand Total) แสดงผลแบบเรียลไทม์ถูกต้องตามราคาสินค้า

### US-04: การสั่งซื้อและการชำระเงินจำลอง (Checkout & Simulated Payment)
* **User Story:** ในฐานะลูกค้า ฉันต้องการสร้างคำสั่งซื้อและแนบหลักฐานการชำระเงินจำลอง เพื่อส่งให้ร้านค้ายืนยันคำสั่งซื้อ
* **Acceptance Criteria:**
  1. เมื่อกดยืนยันการสั่งซื้อ ระบบต้องสร้าง Record ในตาราง Orders และ Order Items พร้อมบันทึกราคา ณ เวลาที่สั่งซื้อ (`unit_price`)
  2. สถานะเริ่มต้นของคำสั่งซื้อต้องเป็น `PENDING` (รอชำระ/รอตรวจสอบ)
  3. ระบบมีฟอร์มให้เลือกวิธีการชำระเงินจำลอง และอัปโหลดไฟล์/URL สลิปจำลอง (ห้ามเชื่อมต่อ Payment Gateway จริงหรือรับข้อมูลบัตรเครดิตจริง)
  4. เมื่อสร้าง Order สำเร็จ รายการในตะกร้าสินค้าของลูกค้ารายนั้นจะต้องถูกเคลียร์ออก

### US-05: การดูประวัติคำสั่งซื้อและการดาวน์โหลด E-Book (Order History & Downloads)
* **User Story:** ในฐานะลูกค้า ฉันต้องการดูประวัติการสั่งซื้อ และเข้าถึงลิงก์ดาวน์โหลดของหนังสือที่คำสั่งซื้อได้รับการอนุมัติแล้ว
* **Acceptance Criteria:**
  1. ลูกค้าสามารถดูรายการคำสั่งซื้อของตนเอง พร้อมวันที่ ยอดเงิน และสถานะ (`PENDING`, `CONFIRMED`, `CANCELLED`)
  2. ลูกค้าจะมองเห็นและคลิกลิงก์ดาวน์โหลด (URL จำลองหรือไฟล์สาธิต) **เฉพาะคำสั่งซื้อที่มีสถานะ `CONFIRMED` เท่านั้น**
  3. หากคำสั่งซื้อยังอยู่ในสถานะ `PENDING` หรือ `CANCELLED` ระบบต้องปิดการเข้าถึงลิงก์ และแสดงข้อความแจ้งเตือนที่เหมาะสม
  4. ลูกค้าไม่สามารถเข้าถึงลิงก์ดาวน์โหลดของหนังสือที่ตนเองไม่ได้สั่งซื้อ (Access Control Verification)

## 2. Admin Module (ระบบจัดการหลังบ้านสำหรับผู้ดูแลร้าน)

### US-06: การจัดการข้อมูล E-Book (E-Book Catalog Management)
* **User Story:** ในฐานะผู้ดูแลร้าน ฉันต้องการเพิ่ม แก้ไข ปิดการขาย และระบุลิงก์ดาวน์โหลดสำหรับหนังสือ E-Book
* **Acceptance Criteria:**
  1. แอดมินสามารถสร้าง E-Book ใหม่โดยกำหนด: ชื่อ, ผู้แต่ง, หมวดหมู่, ราคา ($\ge 0$), คำอธิบาย, รูปภาพปก และ URL ดาวน์โหลด
  2. แอดมินสามารถเปิด/ปิดการเผยแพร่ (`is_active`) ได้ตลอดเวลา
  3. หากกรอกราคาเป็นลบ ระบบต้องปฏิเสธตามเงื่อนไขของฐานข้อมูล (`CHECK (price >= 0)`)

### US-07: การจัดการหมวดหมู่สินค้า (Category Management)
* **User Story:** ในฐานะผู้ดูแลร้าน ฉันต้องการจัดการหมวดหมู่ของ E-Book เพื่อจัดระเบียบสินค้าในร้าน
* **Acceptance Criteria:**
  1. แอดมินสามารถเพิ่ม แก้ไขชื่อหมวดหมู่ได้
  2. ชื่อหมวดหมู่ต้องไม่ซ้ำกันในระบบ (`UNIQUE`)
  3. หากหมวดหมู่มีหนังสือผูกอยู่ การลบหมวดหมู่ต้องถูกปฏิเสธ หรือจัดการ Foreign Key ตามข้อกำหนด (เช่น `RESTRICT`)

### US-08: การตรวจสอบและอัปเดตสถานะคำสั่งซื้อ (Order & Payment Verification)
* **User Story:** ในฐานะผู้ดูแลร้าน ฉันต้องการตรวจสอบคำสั่งซื้อ ดูสลิปจำลอง และเปลี่ยนสถานะเพื่อปลดล็อกลิงก์ดาวน์โหลดให้ลูกค้า
* **Acceptance Criteria:**
  1. แอดมินสามารถค้นหาและคัดกรองคำสั่งซื้อตามสถานะ วันที่สั่งซื้อ หรือชื่อลูกค้าได้
  2. แอดมินสามารถดูรูปสลิปจำลองและยอดเงินที่แจ้งชำระ
  3. แอดมินสามารถอัปเดตสถานะเป็น `CONFIRMED` (เพื่อเปิดสิทธิ์ดาวน์โหลด) หรือ `CANCELLED` (ปฏิเสธคำสั่งซื้อ)
  4. ทุกการเปลี่ยนสถานะต้องบันทึกประวัติหรือ Timestamp ไว้อย่างถูกต้อง

### US-09: การบริหารจัดการผู้ใช้งานและสิทธิ์ (User & Role Management)
* **User Story:** ในฐานะผู้ดูแลร้าน ฉันต้องการตรวจสอบรายชื่อสมาชิก และกำหนดบทบาทผู้ใช้งาน (Customer หรือ Admin)
* **Acceptance Criteria:**
  1. แอดมินสามารถดูรายชื่อผู้ใช้งานทั้งหมด วันที่สมัคร และบทบาทปัจจุบัน
  2. แอดมินสามารถปรับเปลี่ยน Role ของผู้ใช้งานได้

### US-10: แดชบอร์ดและรายงานวิเคราะห์เชิงลึก (Analytics & Reporting)
* **User Story:** ในฐานะผู้ดูแลร้าน ฉันต้องการดูแดชบอร์ดสรุปยอดขาย และรายงานวิเคราะห์ 4 ด้านหลักเพื่อวางแผนธุรกิจ
* **Acceptance Criteria:**
  1. แสดง Dashboard ยอดขายรวม จำนวนคำสั่งซื้อ และจำนวนลูกค้า
  2. แสดงผล 4 รายงานเชิงลึก ได้แก่:
     - รายงานยอดขายตามช่วงเวลา (Daily/Monthly Trend, Average Order Value)
     - รายงาน E-Book ขายดี (Top Selling Books by Quantity/Revenue)
     - รายงานยอดขายตามหมวดหมู่ (Sales & Volume by Category)
     - รายงานพฤติกรรมลูกค้าและสถานะคำสั่งซื้อ (Customer Lifetime Value, Order Status Distribution)
  3. รายงานทั้งหมดต้องประมวลผลผ่านคำสั่ง SQL ที่ใช้ Aggregation (`SUM`, `AVG`, `COUNT`), `JOIN`, `GROUP BY`, `HAVING` จากฐานข้อมูลโดยตรง
  4. รองรับการดูข้อมูลตัวอย่างที่สมเหตุสมผล (อย่างน้อย 30 คำสั่งซื้อ)
