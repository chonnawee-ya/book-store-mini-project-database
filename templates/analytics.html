Monthly Aggregation
{% for row in report1 %} {% endfor %}
เดือน (Sales Month) จำนวนคำสั่งซื้อ (Total Orders) ยอดขายรวม (Total Revenue) ยอดเฉลี่ยต่อคำสั่งซื้อ (AOV)
📅 {{ row.sales_month }} {{ row.total_orders }} รายการ ฿{{ "%.2f"|format(row.total_revenue) }} ฿{{ "%.2f"|format(row.average_order_value) }}
คำสั่ง SQL ที่ใช้ประมวลผล (SQL Query - Report 1) ▼ ดูคำอธิบายคำสั่ง SQL 
SELECT 
    strftime('%Y-%m', o.created_at) AS sales_month,
    COUNT(o.order_id) AS total_orders,
    ROUND(SUM(o.total_amount), 2) AS total_revenue,
    ROUND(AVG(o.total_amount), 2) AS average_order_value
FROM orders o
WHERE o.order_status = 'CONFIRMED'
GROUP BY strftime('%Y-%m', o.created_at)
ORDER BY sales_month DESC;
คำอธิบายหลักการทางฐานข้อมูล:
1. WHERE o.order_status = 'CONFIRMED': กรองเฉพาะคำสั่งซื้อที่ชำระเงินและอนุมัติแล้วเท่านั้น เพื่อความถูกต้องทางบัญชี
2. GROUP BY strftime('%Y-%m', ...): จัดกลุ่มคำสั่งซื้อตาม ปี-เดือน
3. COUNT(), SUM(), AVG(): รวมจำนวนคำสั่งซื้อ ยอดขายรวม และค่าเฉลี่ยคำสั่งซื้อ

อันดับ ชื่อหนังสือ E-Book ผู้แต่ง ยอดขาย (เล่ม) มูลค่ายอดขายรวม (บาท)
#{{ loop.index }} {{ row.title }} {{ row.author_name }} {{ row.units_sold }} เล่ม ฿{{ "%.2f"|format(row.total_sales_amount) }}
คำสั่ง SQL ที่ใช้ประมวลผล (SQL Query - Report 2) ▼ ดูคำอธิบายคำสั่ง SQL 
SELECT 
    b.ebook_id,
    b.title,
    a.name AS author_name,
    COUNT(oi.order_item_id) AS units_sold,
    ROUND(SUM(oi.unit_price), 2) AS total_sales_amount
FROM order_items oi
JOIN orders o ON oi.order_id = o.order_id
JOIN ebooks b ON oi.ebook_id = b.ebook_id
JOIN authors a ON b.author_id = a.author_id
WHERE o.order_status = 'CONFIRMED'
GROUP BY b.ebook_id, b.title, a.name
ORDER BY units_sold DESC, total_sales_amount DESC
LIMIT 5;
คำอธิบายหลักการทางฐานข้อมูล:
1. มีการ JOIN ทั้งหมด 4 ตาราง: order_items, orders, ebooks, authors เพื่อรวมข้อมูลครบถ้วน
2. ใช้ราคา oi.unit_price จากตาราง order_items ซึ่งคงประวัติราคา ณ วันที่ซื้อ (Historical Price Integrity)
3. เรียงลำดับด้วย ORDER BY units_sold DESC, total_sales_amount DESC และตัดเอา 5 อันดับด้วย LIMIT 5

Category Performance
{% for row in report3 %} {% endfor %}
หมวดหมู่ (Category Name) จำนวนคำสั่งซื้อ จำนวนเล่มที่ขายได้ รายได้รวม (บาท)
🏷️ {{ row.category_name }} {{ row.order_count }} คำสั่งซื้อ {{ row.total_books_sold }} เล่ม ฿{{ "%.2f"|format(row.total_revenue) }}
คำสั่ง SQL ที่ใช้ประมวลผล (SQL Query - Report 3) ▼ ดูคำอธิบายคำสั่ง SQL 
SELECT 
    c.category_id,
    c.name AS category_name,
    COUNT(DISTINCT o.order_id) AS order_count,
    COUNT(oi.order_item_id) AS total_books_sold,
    COALESCE(ROUND(SUM(oi.unit_price), 2), 0.00) AS total_revenue
FROM categories c
LEFT JOIN ebooks b ON c.category_id = b.category_id
LEFT JOIN order_items oi ON b.ebook_id = oi.ebook_id
LEFT JOIN orders o ON oi.order_id = o.order_id AND o.order_status = 'CONFIRMED'
GROUP BY c.category_id, c.name
ORDER BY total_revenue DESC;
คำอธิบายหลักการทางฐานข้อมูล:
1. ใช้ LEFT JOIN เพื่อให้หมวดหมู่ที่ยังไม่มียอดขายแสดงขึ้นมาด้วย (ไม่ตกหล่น)
2. ใช้ COALESCE(..., 0.00) เพื่อแปลงค่า NULL ของหมวดหมู่ที่ยังไม่มีการซื้อให้เป็น 0.00 บาทอย่างถูกต้อง

ชื่อลูกค้า อีเมล คำสั่งซื้อทั้งหมด สำเร็จ (Confirmed) รอตรวจ (Pending) ยกเลิก (Cancelled) ยอดใช้จ่ายสะสม (Total Spent)
{{ row.full_name }} {{ row.email }} {{ row.total_orders_placed }} {{ row.confirmed_orders }} {{ row.pending_orders }} {{ row.cancelled_orders }} ฿{{ "%.2f"|format(row.total_spent) }}
คำสั่ง SQL ที่ใช้ประมวลผล (SQL Query - Report 4) ▼ ดูคำอธิบายคำสั่ง SQL 
SELECT 
    u.user_id,
    u.full_name,
    u.email,
    COUNT(o.order_id) AS total_orders_placed,
    SUM(CASE WHEN o.order_status = 'CONFIRMED' THEN 1 ELSE 0 END) AS confirmed_orders,
    SUM(CASE WHEN o.order_status = 'PENDING' THEN 1 ELSE 0 END) AS pending_orders,
    SUM(CASE WHEN o.order_status = 'CANCELLED' THEN 1 ELSE 0 END) AS cancelled_orders,
    COALESCE(ROUND(SUM(CASE WHEN o.order_status = 'CONFIRMED' THEN o.total_amount ELSE 0 END), 2), 0.00) AS total_spent
FROM users u
JOIN orders o ON u.user_id = o.user_id
GROUP BY u.user_id, u.full_name, u.email
HAVING total_orders_placed >= 1
ORDER BY total_spent DESC;
คำอธิบายหลักการทางฐานข้อมูล:
1. ใช้เทคนิค Conditional Aggregation: SUM(CASE WHEN o.order_status = '...' THEN 1 ELSE 0 END) เพื่อ Pivot สถานะคำสั่งซื้อในระดับ SQL เดียวกัน
2. ใช้ HAVING total_orders_placed >= 1 เพื่อกรองเฉพาะสมาชิกที่มีประวัติการสั่งซื้ออย่างน้อย 1 ครั้ง
3. รวมยอดเงินเฉพาะคำสั่งซื้อที่ CONFIRMED เพื่อสะท้อนยอดใช้จ่ายสะสมจริงของลูกค้า
