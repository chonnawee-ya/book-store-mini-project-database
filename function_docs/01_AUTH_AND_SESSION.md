# 01. ระบบยืนยันตัวตน, เซสชัน และสิทธิ์ผู้ใช้งาน (Auth & Session Management)

เอกสารนี้อธิบายขั้นตอนการทำงานของกลุ่มฟังก์ชันที่ดูแลเรื่องการสมัครสมาชิก, การเข้าสู่ระบบ, การตรวจสอบสิทธิ์ และการจัดการสถานะเซสชันในระบบ

---

## 1. `inject_global_data()`
* **ประเภท:** Flask Context Processor
* **การเรียกใช้:** ทำงานอัตโนมัติก่อน Render หน้า Jinja2 Template ทุกหน้า
* **วัตถุประสงค์:** ส่งข้อมูลส่วนกลางที่ต้องแสดงใน Navbar หรือแถบ Header เช่น ข้อมูลผู้ใช้ปัจจุบัน, จำนวนสินค้าในตะกร้า, และรายชื่อบัญชี Demo

### 🔄 ขั้นตอนการทำงาน (Step-by-Step):
1. กำหนดค่าเริ่มต้นตัวแปร `current_user = None`, `cart_count = 0`, และ `demo_users = []`
2. ตรวจสอบว่าใน `session` มีคีย์ `"user_id"` หรือไม่:
   * ถ้ามี: เชื่อมต่อฐานข้อมูลด้วย `get_db_connection()`
   * ดึงข้อมูลผู้ใช้พร้อมชื่อบทบาท (`role_name`) จากตาราง `users` JOIN กับ `roles`
   * ดึงจำนวนไอเทมทั้งหมดในตะกร้าของผู้ใช้คนนั้น โดยนับจากตาราง `cart_items` JOIN กับ `carts` WHERE `c.user_id = ?`
3. ดึงรายชื่อบัญชีจำลอง (Demo Users) สูงสุด 6 บัญชี โดยเรียงลำดับตาม `role_id` เพื่อนำไปแสดงในแถบสลับบัญชีด่วนด้านบน
4. ปิดการเชื่อมต่อฐานข้อมูล (`conn.close()`)
5. ส่งคืน Dictionary `{ "current_user", "cart_count", "demo_users" }` เพื่อให้ HTML Template สามารถเรียกใช้งานได้ทันที

## 2. `login_required(role=None)`
* **ประเภท:** Custom Python Decorator
* **การเรียกใช้:** ห่อหุ้มฟังก์ชัน Route ที่ต้องการป้องกันการเข้าถึง เช่น `@login_required()` หรือ `@login_required(role="ADMIN")`
* **วัตถุประสงค์:** บังคับให้ผู้ใช้งานต้องล็อกอินก่อนเข้าถึงหน้า หรือบังคับว่าต้องเป็น Role ที่กำหนดเท่านั้น (Role-Based Access Control - RBAC)

### 🔄 ขั้นตอนการทำงาน (Step-by-Step):
1. ตรวจสอบว่าใน `session` มี `"user_id"` หรือไม่:
   * **ถ้าไม่มี:** แจ้งเตือนข้อความเตือน `"กรุณาเข้าสู่ระบบก่อนดำเนินการ"` และ Redirect ไปยังหน้าล็อกอิน (`/login`)
2. ตรวจสอบกรณีที่มีการระบุเงื่อนไขบทบาท (`role` เช่น `"ADMIN"`):
   * เปิดการเชื่อมต่อฐานข้อมูล
   * ดึงค่า `role_name` จากตาราง `roles` ของ `user_id` ในเซสชันปัจจุบัน
   * ตรวจสอบว่า `role_name == role` หรือไม่
   * **ถ้าสิทธิ์ไม่ตรง:** แจ้งเตือน `"คุณไม่มีสิทธิ์เข้าถึงหน้านี้ (Admin Only)"` และ Redirect กลับหน้าแรก (`/`)
3. **ถ้าผ่านเงื่อนไขทั้งหมด:** อนุญาตให้รันฟังก์ชัน Route เดิมต่อไปได้ตามปกติ

## 3. `demo_switch(user_id)`
* **Route:** `/demo/switch/<int:user_id>` (GET)
* **สิทธิ์การเข้าถึง:** ทุกคน (สำหรับการทดสอบและนำเสนอผลงาน)
* **วัตถุประสงค์:** สลับสิทธิ์ผู้ใช้งานใน Session แบบคลิกเดียว เพื่อความสะดวกในการตรวจข้อสอบหรือสาธิตระบบ

### 🔄 ขั้นตอนการทำงาน (Step-by-Step):
1. รับ `user_id` จาก URL Parameter
2. คิวรีฐานข้อมูลหาข้อมูลผู้ใช้คนนั้น:
   ```sql
   SELECT u.*, r.role_name FROM users u
   JOIN roles r ON u.role_id = r.role_id
   WHERE u.user_id = ?
   ```
3. หากพบผู้ใช้:
   * อัปเดตข้อมูลในเซสชัน:
     * `session["user_id"] = user["user_id"]`
     * `session["user_name"] = user["full_name"]`
     * `session["role_name"] = user["role_name"]`
   * แจ้งเตือน Flash message ว่าสลับเป็นผู้ใช้ใดแล้ว
4. ส่งผู้ใช้กลับไปยังหน้าเดิมที่กดมา (`request.referrer`) หรือหน้าแรก

## 4. `register()`
* **Route:** `/register` (GET, POST)
* **สิทธิ์การเข้าถึง:** ผู้เยี่ยมชมทั่วไป
* **วัตถุประสงค์:** สมัครสมาชิกลูกค้าใหม่ และสร้างตะกร้าสินค้า (Cart) ประจำตัวทันที

### 🔄 ขั้นตอนการทำงาน (Step-by-Step):
1. **เมื่อเป็นคำขอ GET:** แสดงหน้าฟอร์มสมัครสมาชิก (`register.html`)
2. **เมื่อเป็นคำขอ POST:**
   * ดึงค่าจากฟอร์ม: `full_name`, `email` (แปลงเป็น lowercase), `password`, `phone`
   * ตรวจสอบความครบถ้วนของข้อมูลที่จำเป็น (Validation)
   * ตรวจสอบเงื่อนไข **UNIQUE Email Constraint**:
     ```sql
     SELECT user_id FROM users WHERE email = ?
     ```
     ถ้าพบว่าอีเมลซ้ำ จะแจ้งเตือนและหยุดการบันทึก
   * ทำการแฮชรหัสผ่านด้วยอัลกอริทึมความปลอดภัยสูงผ่าน `generate_password_hash(password)`
   * เริ่มการบันทึกข้อมูล (INSERT เข้าตาราง `users` ด้วยสิทธิ์ `role_id = 2` หรือ CUSTOMER)
   * ดึง `user_id` ใหม่ที่เพิ่งถูกสร้างขึ้นมา (`cur.lastrowid`)
   * **สร้างตะกร้าสินค้าเริ่มต้นทันที (Relationship 1:1 ระหว่าง User กับ Cart):**
     ```sql
     INSERT INTO carts (user_id) VALUES (?)
     ```
   * ทำการ `conn.commit()` เพื่อบันทึกข้อมูลอย่างถาวร
   * เข้าสู่ระบบให้อัตโนมัติโดยเก็บค่าลง `session` และ Redirect ไปยังหน้าแรก

## 5. `login()`
* **Route:** `/login` (GET, POST)
* **สิทธิ์การเข้าถึง:** ผู้เยี่ยมชมทั่วไป
* **วัตถุประสงค์:** ตรวจสอบอีเมลและรหัสผ่านเพื่อเข้าสู่ระบบ

### 🔄 ขั้นตอนการทำงาน (Step-by-Step):
1. **เมื่อเป็นคำขอ GET:** แสดงหน้าฟอร์มเข้าสู่ระบบ (`login.html`)
2. **เมื่อเป็นคำขอ POST:**
   * ดึงค่า `email` และ `password` จากฟอร์ม
   * คิวรีค้นหาผู้ใช้จากตาราง `users` โดยใช้ Prepared Statement:
     ```sql
     SELECT u.*, r.role_name
     FROM users u
     JOIN roles r ON u.role_id = r.role_id
     WHERE u.email = ?
     ```
   * ตรวจสอบรหัสผ่านที่ส่งมา เทียบกับรหัสผ่านที่แฮชไว้ในฐานข้อมูลด้วย `check_password_hash(user["password_hash"], password)`
   * **หากถูกต้อง:** บันทึก `user_id`, `user_name`, `role_name` ลงใน `session` และ Redirect ไปหน้าแรก
   * **หากไม่ถูกต้อง:** แจ้งเตือนข้อผิดพลาด `"อีเมลหรือรหัสผ่านไม่ถูกต้อง"` และคงอยู่ที่หน้าเดิม

## 6. `logout()`
* **Route:** `/logout` (GET)
* **สิทธิ์การเข้าถึง:** สมาชิกที่เข้าสู่ระบบแล้ว
* **วัตถุประสงค์:** สิ้นสุดเซสชันการใช้งานปัจจุบัน

### 🔄 ขั้นตอนการทำงาน (Step-by-Step):
1. เรียกคำสั่ง `session.clear()` เพื่อล้างข้อมูลทั้งหมดในคุกกี้เซสชันของเซิร์ฟเวอร์
2. ส่ง Flash Message แจ้งเตือน `"ออกจากระบบเรียบร้อยแล้ว"`
3. Redirect ผู้ใช้กลับไปยังหน้าแรก (`index`)
